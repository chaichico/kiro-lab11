📋 Executive Dashboard

What is this system? Wild Rydes is an online ride-sharing service where customers request unicorn rides through a web browser. Users register, log in, pick locations on a map, and get assigned a unicorn for their trip. It serves as a demonstration application for AWS services integration.

Security Assessment

🔴 Unsalted SHA-256 Password Hashing — Passwords vulnerable to rainbow table attacks. Must replace with bcrypt/PBKDF2 with per-user salt.
🔴 Open Redirect Vulnerability — Login redirects to unvalidated user-supplied URL via ?or= parameter. Enables phishing attacks.
🟠 Missing CSRF on API Endpoints — CreateRide and ReverseGeocode lack anti-forgery token validation. Cross-site request forgery possible.
🟠 Information Disclosure — Exception messages returned to client in CreateRide catch block. May leak internal system details.
🔵 Hardcoded Credentials in Seed Data — Default user credentials in source code (user@unicornrides.aws / Passw0rd). Risk if seed runs in production.

Remediation Priorities

Priority 1 — Immediate (Before Migration)

  • Fix unsalted password hashing — Replace SHA-256 with bcrypt/PBKDF2 with per-user salt
  • Fix open redirect — Validate redirect URL is local using Url.IsLocalUrl()
  • Add CSRF to API endpoints — Protect CreateRide and ReverseGeocode
  • Remove hardcoded credentials — Externalize seed data configuration

Priority 2 — During Migration

  • Migrate to .NET 8 — Port all code to ASP.NET Core with DI, Kestrel, middleware
  • Replace EF6 with EF Core — Migrate DbContext, models, recreate migrations
  • Implement proper auth — Integrate Amazon Cognito User Pools for user authentication
  • Add test suite — Create xUnit project with 80%+ coverage target

Priority 3 — Post-Migration

  • Remove obsolete dependencies — Drop Modernizr, WebGrease, Antlr
  • Separate API layer — Dedicated API controllers for JSON endpoints
  • Add CDN for static assets — CloudFront + S3 for CSS/JS/images
  • Implement CI/CD — Automated testing and deployment pipeline
